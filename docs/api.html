Management API reference

Query Minecraft Java proxy status and traffic metrics, and manage routes and global settings. By default, the management API is exposed through the same-origin HTTPS console.

Base URL: /api/v1JSONBearer Tokenv0.15.0

Authentication

Every endpoint except /healthz requires Authorization: Bearer <admin-token>. Set the token with the server-side MC_PROXY_ADMIN_TOKEN environment variable; it must contain at least 32 characters.
Authorization: Bearer your-admin-token
Content-Type: application/json
GET/healthz

Health check

Returns a simple response for Nginx, systemd, or monitoring. YvLink does not require a Bearer token for this endpoint.

Request parameters

None.

Successful response
HTTP/1.1 200 OK
ok
Errors

An upstream proxy may return 502 when the service is unavailable.

Mod loader handshake counters
FieldDescription
unmarked_handshakesHandshakes without a mod loader marker in the host field. Vanilla and Fabric cannot be reliably distinguished here.
legacy_forge_handshakesLegacy Forge handshakes marked with FML.
modern_forge_login_handshakesForge handshakes marked with FML2 or FML3, negotiated during Login.
configuration_forge_handshakesForge or NeoForge handshakes marked with FORGE or a 1.20.2+ Configuration suffix.

These counters inspect only the initial handshake host marker. They do not count successful logins or decode later protocol phases.

Backend health fields

health is unknown, healthy, or unhealthy. last_checked_secs_ago measures time since the last completed probe. Total and consecutive success/failure counters support monitoring and health thresholds. A successful tcp probe confirms only that the port is reachable; a successful minecraft-status probe also validates the Java handshake, Status JSON, and Ping/Pong. Neither guarantees that a player can log in.

Errors

401:Authentication failed.

GET/api/v1/updates

Read automatic update status

Reads the latest status file written by the systemd updater. This API does not download updates or restart the service. The console uses the result to show completed, failed, and rolled-back updates.

Request parameters

None.

Successful response
{"ok":true,"data":{"current_version":"0.15.0","status":{"state":"up-to-date","message":"Already up to date: v0.15.0."}}}
Status fields
FieldDescription
current_versionCurrent running version of YvLink.
status.stateup-to-date,downloading,updated,deferred,failed,rolled-back or unknown.
status.messageLatest updater message shown to administrators.
Errors

401: Authentication failed. If the updater has not run or its status file is unreadable, the API returns 200 with status.state="unknown" and an explanatory message.

GET/api/v1/via

Read ViaLite configuration and status

Returns the managed ViaLite configuration and subprocess status. ViaLite sits between YvLink routing and the real Java backend. When running=true, backend connections use its loopback translation listeners.

Request parameters

None.

Successful response
{"ok":true,"data":{"config":{"enabled":true,"binary_path":"/opt/mc-proxy/vialite/vialite","runtime_dir":"/run/mc-proxy/vialite","gate_protocol":"auto","backend_version":"auto"},"runtime":{"available":true,"enabled":true,"running":true,"managed_backends":2,"error":null}}}
Errors

401:Authentication failed.

PUT/api/v1/via

Modify ViaLite configuration

Atomically saves the ViaLite configuration and rebuilds a separate subprocess and loopback listener for each unique backend. If startup fails, the saved configuration remains and runtime.error reports the cause; connections fall back to the real backend.

Request Body Parameters
FieldsTypeConstraints and description
enabledBooleanWhether to enable ViaLite backend Java protocol conversion.
binary_pathString/nullAbsolute path to the native ViaLite executable when enabled.
runtime_dirStringDirectory for temporary JSON configuration; the production systemd default is /run/mc-proxy/vialite.
gate_protocolStringProtocol used from YvLink to ViaLite, usually auto.
backend_versionStringProtocol used from ViaLite to the backend. auto detects the backend version; set it explicitly if detection is unsuitable.
Example request
{"enabled":true,"binary_path":"/opt/mc-proxy/vialite/vialite","runtime_dir":"/run/mc-proxy/vialite","gate_protocol":"auto","backend_version":"auto"}
Errors

400: Invalid path or protocol, or a route has PROXY Protocol enabled. 401: Authentication failed.

Read Bedrock crossplay status

Returns crossplay configuration and Geyser runtime status. When enabled, YvLink sends a RakNet Unconnected Ping to the Bedrock UDP port. online=true means the translator replied. PUT/api/v1/crossplay

Update Bedrock crossplay

Validates and atomically saves crossplay settings, then immediately runs a RakNet health probe. external uses a separate Geyser Standalone process; geyserlite starts a translator managed by YvLink. A startup failure is reported in runtime.error without reverting the saved configuration. GeyserLite requires a build with available=true.

Request Body Parameters
FieldsTypeConstraints and description
enabledBooleanEnable crossplay health monitoring.
providerEnumexternal for a separate Geyser Standalone process, or geyserlite for the hosted translator.
bedrock_listenSocketAddrExpected Geyser Bedrock UDP listen address; port must be nonzero.
java_addressStringHostname used by Geyser for Java. It must match an enabled route with crossplay_enabled=true and resolve locally to YvLink.
java_portInteger1–65535; usually the YvLink Java listen port.
auth_typeEnumonline, floodgate, or offline. Floodgate requires compatible backend setup.
geyserliteObjectManaged translator settings used when provider is geyserlite.
geyserlite Parameters
FieldsTypeConstraints and description
modeEnumembedded (in process, default) or subprocess (isolated process).
library_pathString/nullExplicit libgeyserlite.so path for embedded mode; mutually exclusive with binary_path.
binary_pathString/nullNative executable path for subprocess mode; mutually exclusive with library_path.
offlineBooleanDisallow automatic downloads; a local library or executable must be available.
motd_line1/motd_line2StringTwo lines of the Bedrock server list MOTD.
floodgate_keyString/nullFor Floodgate authentication: a sensitive 16-byte AES-128 key.
Example request
{"enabled":true,"provider":"geyserlite","bedrock_listen":"0.0.0.0:19132","java_address":"bedrock.example.com","java_port":25565,"auth_type":"online","geyserlite":{"mode":"embedded","library_path":null,"binary_path":null,"offline":false,"motd_line1":"YvLink","motd_line2":"Bedrock via GeyserLite","floodgate_key":null}}
Successful response

200: Same structure as the GET response.

Errors

400: Invalid address, port, mode, paths, Floodgate key, Java route, or persistence failure. 401: Authentication failed. GeyserLite startup failure returns 200 with details in runtime.error.

POST/api/v1/rules

Create route

Creates and atomically saves a host-to-backend route. YvLink uses the first route whose host pattern matches the initial Java handshake. A new route is inserted before an enabled catch-all * route.

Request Body Parameters
FieldsTypeConstraints and description
idStringUnique identifier: 1–32 letters, digits, hyphens, or underscores.
nameString1–64 characters.
hostString arrayOne or more handshake host patterns. * and ? wildcards are supported; matching is case insensitive.
backendString array1–128 host:port addresses. TOML also accepts a legacy single string; the JSON API uses an array.
strategyEnumerationsequential,random,round-robin,least-connections or lowest-latency.
proxy_protocolEnumoff, v1, or v2 (default: off). The backend must support the selected version. In TOML, legacy true means v1.
health_checkObjectOptional active probes. mode is tcp or minecraft-status. Configure enabled, interval_secs (1–86400), timeout_ms (100–60000 and no longer than the interval), and healthy/unhealthy thresholds (1–100). At most 64 probes run concurrently.
health_check.minecraft_hostString/nullHandshake host for Status probes, 1–255 bytes, without wildcards, whitespace, or NUL. If omitted, an exact route host is preferred; wildcard routes or host rewriting use the backend hostname.
health_check.minecraft_protocolIntegerStatus probe protocol number, 0–2,147,483,647 (default: 769). The returned version may differ, but the response must include version, players, and description.
modify_virtual_hostBooleanRewrite the forwarded Minecraft handshake host to the backend hostname.
crossplay_enabledBooleanAllow this route as the Java upstream for global Bedrock crossplay (default: false). crossplay.java_address must match an enabled allowed route.
statusObject/nullOptional server list response. custom generates it locally; backend reads backend Status JSON and preserves Forge metadata, favicon, player samples, and unknown fields.
status.cache_ttl_secsInteger-1–86400. In backend mode, responses are cached by backend and client protocol; -1 or 0 disables reuse.
Status override fieldsOptionalmotd, version_name, protocol, online, and max. In backend mode, only non-null values override the backend response.
status.fallbackObject/nullFallback response when backend connection, timeout, or JSON parsing fails; uses the same fields as status overrides.
whitelist_enabledBooleanCheck player names against the proxy whitelist during Login Start.
whitelistString arrayUp to 10,000 case-insensitive names of 1–16 letters, digits, or underscores.
whitelist_messageStringDisconnect message for players outside the whitelist; 1–1024 characters, plain text, § codes, or a JSON text component.
enabledBooleanWhether this route participates in matching.
Example request
{"id":"mod","name":"Modded","host":["mod.example.com"],"backend":["backend-a.example.com:25565","backend-b.example.com:25565"],"strategy":"least-connections","proxy_protocol":"v2","health_check":{"enabled":true,"mode":"minecraft-status","interval_secs":30,"timeout_ms":2000,"unhealthy_threshold":3,"healthy_threshold":2,"minecraft_host":"mod.example.com","minecraft_protocol":769},"modify_virtual_host":true,"status":{"mode":"backend","cache_ttl_secs":60,"motd":"§bModded server online","version_name":null,"protocol":null,"online":null,"max":null,"fallback":{"motd":"§cBackend temporarily offline","version_name":"Maintenance","protocol":-1,"online":0,"max":100}},"whitelist_enabled":false,"whitelist":[],"whitelist_message":"§cYou are not in the whitelist of this server.","crossplay_enabled":true,"enabled":true}
Successful response

201: Created route.

Errors

400: Duplicate ID/host, invalid settings, listener reload failure, or persistence failure. 401: Authentication failed.

PUT/api/v1/rules/{id}

Update route

Replaces a route. The path ID overrides any ID in the request body. Route changes reload the shared listener. While crossplay is enabled, its Java address must continue to match an enabled route that allows crossplay.

Path parameters
idRoute ID.
Request

Same fields as Create route.

Successful response

200: Updated route.

Errors

400: Route not found, invalid settings, listener failure, or persistence failure. 401: Authentication failed.

DELETE/api/v1/rules/{id}

Stops and removes a route. At least one route must remain in the configuration; it may be disabled.
